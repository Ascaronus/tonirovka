# SEO Audit Report — tonirovka.kh.ua

Дата: 2026-03-03
Формат сайта: одностраничный (SPA-like, server-rendered HTML)

## 1) Executive Summary

Сайт уже имеет хороший базовый SEO-фундамент (canonical, sitemap, robots, structured data, HTTPS-редиректы).
Основные ограничения роста органики сейчас связаны не с "поломкой", а с архитектурой:

- один URL для двух языков (uk/ru),
- часть технических сигналов конфликтует с мультиязычностью,
- есть точки улучшения по Core Web Vitals и crawl quality.

## 2) Что уже сделано хорошо

- Есть `canonical` на главную: `https://tonirovka.kh.ua/`.
- Есть `sitemap.xml` и `image-sitemap.xml`.
- В `robots.txt` указаны обе карты сайта.
- Настроены 301 редиректы в `.htaccess` (`www -> non-www`, `http -> https`, `index.html -> /`).
- Есть Open Graph / Twitter мета.
- Есть structured data (LocalBusiness, BreadcrumbList) и FAQ-разметка.
- Добавлены удобные имена файлов галереи (`foto1...`) и корректные пути `images/gallery/` для image sitemap.

## 3) Критичные риски (High)

### H1. Языковая SEO-стратегия конфликтная

Файлы: `index.html`, `.htaccess`, `sitemap.xml`

- `hreflang="uk"` и `hreflang="ru"` указывают на один и тот же URL.
- `/ru/` редиректится на `/`.

Последствие:
- Google не может полноценно индексировать отдельную RU-версию как отдельный URL.
- Потенциал роста по русскоязычной семантике ограничен.

Решение (выбрать один путь):
1) Либо делаем отдельные URL (`/uk/`, `/ru/`) + корректный `hreflang` + self-canonical.
2) Либо оставляем один URL и убираем видимость «двух языковых версий» как разных страниц.

### H2. Ошибки 404/403 лучше отдавать отдельными страницами

Файл: `.htaccess`

Сейчас `ErrorDocument` уже улучшен в сторону `/`, но для максимального SEO-контроля лучше:
- `ErrorDocument 404 /404.html`
- `ErrorDocument 403 /403.html`

С правильными HTTP-статусами.

Последствие:
- лучше диагностика в Search Console,
- меньше риска soft-404 сигналов.

## 4) Важные улучшения (Medium)

### M1. Улучшить загрузку изображений

Файлы: `index.html`, `css/main.css`

- Добавить `loading="lazy"` и `decoding="async"` для не-критичных изображений.
- Для hero (LCP) использовать приоритетную стратегию загрузки (preload/fetchpriority/high-priority resource).

Ожидаемый эффект:
- лучше mobile speed и Core Web Vitals.

### M2. Нормализовать кеш-заголовки для изображений

Файл: `.htaccess`

- Избегать искусственного `Last-Modified: 1970` для картинок.
- Использовать нормальные `Cache-Control` + `ETag/Last-Modified` от сервера.

### M3. Привести image-sitemap к единому языковому стилю

Файл: `image-sitemap.xml`

- Держать единый стиль title/caption (например, украинский как основной), без смешения стилей в одном sitemap.

## 5) Низкий приоритет (Low, но полезно)

- Перевод изображений в WebP/AVIF.
- Добавление `srcset/sizes` для адаптивных изображений.
- Удаление устаревших/малополезных meta (`keywords` и др. шумовые теги).

## 6) Search Console: как трактовать статусы

### "Страница с переадресацией"
Обычно это нормальный статус при корректных 301.

### "Вариант страницы с тегом canonical"
Для `.../index.html` при canonical на `/` — это ожидаемо.

Когда это ОК:
- индексируется канонический URL `https://tonirovka.kh.ua/`;
- дубль `index.html` не индексируется отдельно.
