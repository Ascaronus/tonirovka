# tonirovka.kh.ua

Полный проект из `site.zip`: публичная HTML-страница, CSS/JS, переводы,
изображения и PHP-админка. Основной адрес: https://tonirovka.kh.ua/.

## Развёртывание на существующий Cityhost

1. Сохраните резервную копию файлов сайта и базы данных на хостинге.
2. Скачайте актуальную ветку `main` (Code → Download ZIP), распакуйте архив.
   Загружайте **содержимое** каталога `tonirovka-main`, а не сам каталог,
   в существующий корень сайта. Не удаляйте файлы перед загрузкой.
3. Загрузите с заменой `.htaccess`, `index.html`, `403.html`, `404.html`,
   `robots.txt`, обе карты сайта и папки `admin`, `css`, `js`, `langs`, `images`.
   Также загрузите `data/.htaccess`. Включите отображение скрытых файлов в FTP-клиенте.
4. **Сохраните существующий `admin/.env`, базу данных, резервные копии и новые
   изображения на хостинге.** В GitHub нет рабочих паролей. Не заменяйте `.env`
   файлом `.env.example`. SQL-файлы из архива — прежние вспомогательные файлы;
   для этого обновления импортировать их не нужно.
5. `.github`, `tests`, `.git`, Docker-файлы и Markdown-документация на хостинге
   не нужны. Существующие каталоги `data` и `images` не очищайте.
6. Очистите кеш хостинга/CDN, если включён. Проверьте главную в приватном окне,
   вход в админку, переключение языков и галерею.
7. Проверьте ответы из таблицы ниже. Настройки nginx/CDN/панели хостинга могут
   исполняться раньше `.htaccess`: если остаётся цикл, проверьте редиректы там.

Требуется Apache 2.4 (или совместимая обработка `.htaccess`), mod_rewrite,
разрешённые AllowOverride и PHP с DOM, PDO MySQL и GD для админки.
Сам сайт отдаётся статически и не требует подключения к БД для посетителя.
Архив не является полным SQL-дампом текущей БД: он предназначен для обновления
существующего сайта, а не автоматического восстановления новой БД.

## Что исправлено

- `/?lang=ru` и `/?lang=uk`: удаление query string через QSD, без редиректа на себя.
- `/index.html`: редирект только при явном запросе клиента (THE_REQUEST).
  Внутреннее открытие DirectoryIndex больше не редиректит главную на себя.
- HTTP, www и известные старые страницы нормализуются без лишнего промежуточного
  перехода на уровне правил этого проекта. Внешний прокси может добавить свой переход.
- Старые services/prices/portfolio/contacts ведут к соответствующим разделам.
  Произвольные отсутствующие URL, в том числе `/ru/unknown`, возвращают 404.
- Убраны объявления разных языковых страниц с одним и тем же URL.
  Украинский HTML остаётся основной индексируемой страницей; русский доступен
  кнопкой, как раньше. Для самостоятельной индексации русского нужны отдельный
  URL, серверный русский HTML и полноценная схема canonical/hreflang — здесь
  такие страницы не создаются.
- Генератор sitemap и админские проверки приведены к той же модели.
  Карта изображений берёт существующие изображения из опубликованного HTML,
  включая главное OG-изображение, удаляет параметры кеширования и дубли.
- lastmod не меняется только от запуска генератора; при редактировании контента
  админка обновляет обе карты. После ручного изменения HTML обновите lastmod сами.
- При смене языка JS сохраняет остальные параметры URL и якорь; первый визит
  показывает тот же украинский язык, что и исходный HTML.
- Закрыт HTTP-доступ к `.env`, служебным файлам, дампам и резервным копиям;
  админка получает X-Robots-Tag: noindex. На входе обновляется ID сессии.
- В Docker Compose убрано перекрытие значений env_file пустыми переменными.

## Ожидаемые HTTP-ответы

| Адрес | Ответ |
|---|---|
| `https://tonirovka.kh.ua/` | 200, canonical на себя |
| `/robots.txt`, `/sitemap.xml`, `/image-sitemap.xml` | 200 |
| HTTP или www | 301 на HTTPS без www |
| `/index.html`, `/?lang=ru`, `/ru/` | 301 на главную без цикла |
| `/prices.html` | 301 на `/#pricing` |
| `/missing-page`, `/ru/missing-page`, `/404.html` | 404 |
| `/admin/.env`, `/data/backups/...` | 403 |
| `/admin/` | страница входа; noindex |

Смешанные query string, например `?lang=ru&utm_source=...`, не редиректятся
безусловно с потерей маркетинговых параметров: canonical остаётся на главную,
JS удаляет только lang. В sitemap есть только чистый основной URL.

## Проверки

- `python3 tests/check_seo.py` — XML/JSON, canonical, локальные ссылки,
  изображения, якоря, JSON-LD.
- `node --check js/main.js` — синтаксис JavaScript.
- GitHub Actions `SEO and redirect checks` запускает PHP lint, генератор обеих
  карт и HTTP-тесты на настоящем Apache в контейнере. Проверяет GET/HEAD,
  X-Forwarded-Proto/X-Forwarded-SSL, www, старые адреса, 404, запрет служебных
  файлов и доступность ресурсов. Это не тест реальной конфигурации Cityhost.

Старые SEO-отчёты в репозитории сохранены как история; они не доказывают
актуальное состояние сайта. Полную работу форм админки с вашей БД без доступа
к ней проверить нельзя. В существующей админке есть условные/имитационные
оценки скорости; для реальной скорости нужен отдельный замер.

## Google Search Console после загрузки

Отправьте `https://tonirovka.kh.ua/sitemap.xml` и
`https://tonirovka.kh.ua/image-sitemap.xml`. Проверьте основной URL через
«Проверка URL» → «Проверить опубликованную страницу», затем запросите индексацию.
В отчёте об ошибках переадресации запустите проверку исправления.
Статус «Страница с переадресацией» для HTTP, www и старых URL ожидаем:
индексироваться должна конечная страница. Исчезновение всех записей об этих
URL не является целью; индексацию и сроки определяет Google.

Основания: [редиректы Google](https://developers.google.com/search/docs/crawling-indexing/301-redirects),
[языковые версии](https://developers.google.com/search/docs/specialty/international/localized-versions),
[флаги Apache](https://httpd.apache.org/docs/2.4/rewrite/flags.html).

## Файлы, намеренно не опубликованные

- `admin/.env` — реальные реквизиты БД и хеш пароля.
- Два JSON-файла в `data/backups/` — старые снимки кода/БД; в одном обнаружены
  реальные реквизиты подключения. Сохраняйте их только приватно.
- `data/last_auto_backup.txt` — локальное состояние автоматического бэкапа.
- Две копии `images/3.jpg.backup.*` — неиспользуемые резервные копии изображения.

Структура `data/backups/` сохранена через `.gitkeep`; все рабочие изображения,
PHP-файлы, CSS, JS и JSON-переводы присутствуют. `.env.example` содержит только
пустой шаблон. Gitignore и Dockerignore предотвращают повторную публикацию
секретов и резервных копий.
