# tonirovka.kh.ua

Полный проект из `site.zip`: публичная HTML-страница, CSS/JS, переводы,
изображения и PHP-админка. Основной адрес: https://tonirovka.kh.ua/.

## Email в виде кликабельного изображения

В контактах и футере используется предоставленная картинка tools.org.ua, ссылка
открывает `mailto:tonirovka.kh.ua@gmail.com`. Адрес остаётся в исходном коде:
это способ отображения, а не защита от сбора email. Картинка загружается с внешнего сервиса.
Переключение языка и сохранение контента сохраняют изображение. Если изменить адрес
в админке, он отобразится обычным текстом: старая картинка соответствует только прежнему адресу.

Для установки загрузите `index.html`, `js/main.js`, `css/page-layout.css` и
`admin/content.php`. Сохраните текущие тексты при объединении с копией хостинга.

## Уменьшение HTML без сокращения контента

Размер исходного `index.html` уменьшен с 86 043 до 71 078 байт (примерно на 17%).
Нормализованный видимый текст не изменился: 14 134 байта UTF-8. По отношению
этих величин доля текста выросла с 16,43% до 19,89%. Это локальная методика,
она не воспроизводит алгоритм стороннего SEO-анализатора и его прежние 7%.

Украинские тексты блока рекомендаций больше не повторяются в атрибутах HTML:
они остаются непосредственно на странице и доступны без JavaScript. Русские
переводы сохранены. Редактор понимает старый и новый формат, переключение языков
сохраняется. JSON-LD уплотнён без удаления данных; лишние отступы перед тегами
убраны. При публикации через админку форматирование снова не раздувает HTML.

Для установки загрузите `index.html`, `js/main.js`, `admin/admin_runtime.php`,
`admin/html_compact.php`, `admin/guide_helper.php` и `admin/.htaccess`.
Если тексты на хостинге менялись, сначала объедините текущую страницу с обновлением.
SQL и robots.txt менять не нужно. После публикации обновите карты через админку.

## Dublin Core

В `index.html` добавлены название, описание, язык, тематика, издатель, адрес,
тип и формат страницы в метаданных Dublin Core. Дизайн страницы не меняется.
`DC.title` и `DC.description` обновляются вместе с SEO-полями через админку;
при переключении языка используются соответствующие переводы.
Для установки этого дополнения перенесите `index.html` и `admin/seo_tools.php`.
Существующие настройки БД, robots.txt и список URL в картах не меняются.
После публикации обновите карты через SEO-автоматику для актуализации lastmod.

## Дополнение: заголовки, стили печати и Apple-иконка

Для этого обновления загрузите `index.html`, `css/page-layout.css`, `css/print.css`,
`css/noscript.css`, `images/apple-touch-icon.png`, `admin/content.php` и `admin/settings.php`.
Текущий `css/main.css` сохраняется; в HTML обновлён его параметр кеширования.
Если опубликованный контент отличается от GitHub, перед заменой `index.html` объедините
изменения с текущей копией, чтобы сохранить ваши тексты. SQL-импорт не требуется.

Украинский title содержит 70 символов, description — 160, включая пробелы.
Те же тексты применяются в Open Graph и Twitter; русские метаданные также сокращены.
Уточнены заголовки редактируемого блока о защитных плёнках. Его восемь карточек
по-прежнему управляются через раздел админки с рекомендациями по выбору плёнки.
SEO-тексты доступны в настройках и SEO-автоматике. Автоматическую подстановку из
первого экрана оставьте выключенной, если хотите сохранить эти ручные метаданные.

Публичные CSS-атрибуты вынесены в отдельный файл; генератор контактов в админке
публикует те же классы. JS для динамического положения кнопок и внешние виджеты
могут добавлять стили уже в браузере. Добавлена отдельная таблица стилей печати и
PNG-иконка 180×180 для добавления сайта на экран Apple-устройства.

## Обновление на существующем Cityhost — MySQL 5.7

**Оставьте установленную MySQL 5.7.** Обновлять сервер БД, переходить на MariaDB,
создавать новую базу или импортировать SQL-файлы для этого обновления не нужно.
Полный прогон админки выполнен на MySQL 5.7.44:
[результаты проверки](https://github.com/Ascaronus/tonirovka/actions/runs/35598049763).
Docker и тестовая база используются только в CI, на хостинге их устанавливать не нужно.

### Если предыдущие изменения сайта уже установлены

1. Сохраните резервную копию файлов и экспорт рабочей БД через панель хостинга.
2. Скачайте ветку `main` (Code → Download ZIP) и распакуйте архив.
3. Загрузите с заменой файлы из `admin/` и `js/main.js` в одноимённые каталоги
   существующего сайта. Включите отображение скрытых файлов и перенесите
   `admin/.htaccess`. Существующий `admin/.env` сохраните без изменений.
4. В текущем `index.html` у подключения `js/main.js` установите версию
   `js/main.js?v=20260921-admin-audit`. Сам `index.html` целиком не заменяйте,
   если после выгрузки проекта редактировали тексты через админку.
5. Сохраните рабочие `data/`, `langs/`, `images/`, резервные копии и БД.
   Не заменяйте `.env` файлом `.env.example`. Старые SQL-скрипты не запускайте.
6. Очистите кеш хостинга/CDN, если он включён. Войдите в админку, откройте
   SEO-автоматику, обновите карты/разметку и запустите проверку. Проверьте
   сохранение текста, оба языка и открытие `/sitemap.xml` и `/image-sitemap.xml`
   с HTTP 200. Проверка из админки не заменяет проверку внешнего доступа Google.

Каталоги `.github`, `tests`, `.git`, Docker-файлы и документация на хостинге не нужны.
Тестовый скрипт `tests/seed_admin.php` на рабочем хостинге запускать нельзя.

### Если ранние исправления ещё не загружены

Кроме файлов выше потребуются корневой `.htaccess`, `403.html`, `404.html`,
`robots.txt`, `data/.htaccess` и обновлённые публичные CSS/JS. Изменения шаблона
`index.html`, переводов и изображений нужно объединить с текущим содержимым
хостинга, если оно уже отличается от репозитория. Полная замена этих файлов
копией из GitHub может затереть изменения, сделанные через админку.

### Среда и права

Используются Apache 2.4 (или совместимая обработка `.htaccess`), mod_rewrite,
AllowOverride и PHP с DOM, PDO MySQL и GD для обработки изображений.
Проверенный стенд — PHP 8.2 и MySQL 5.7.44; версия PHP на вашем хостинге пока
не подтверждена. Совместимость БД не подтверждает совместимость с любой версией PHP.

PHP нужны права записи в `index.html`, карты сайта, `langs/`, `images/`, `data/`
и в существующий `admin/.env` для смены пароля. Откат транзакций требует InnoDB;
движки рабочих таблиц ещё необходимо сверить при доступе к phpMyAdmin.
Сайт для посетителя статический. Архив проекта не содержит дамп рабочей БД.

Подробнее: [исправления, SEO-автоматика и порядок обновления](ADMIN-AUDIT-20260921.md).

## Что исправлено

- `/?lang=ru` и `/?lang=uk`: удаление query string через QSD, без редиректа на себя.
- `/index.html`: редирект только при явном запросе клиента (THE_REQUEST).
  Внутреннее открытие DirectoryIndex больше не редиректит главную на себя.
- HTTP, www и известные старые страницы нормализуются без лишнего промежуточного
  перехода на уровне правил этого проекта. Внешний прокси может добавить свой переход.
- Старые services/prices/portfolio/contacts ведут к соответствующим разделам.
  Произвольные отсутствующие URL, в том числе `/ru/unknown`, возвращают 404.
- Убраны объявления разных языковых страниц с одним и тем же URL.
  Украинский HTML остаётся основной индексируемой страницей; русский доступен
  кнопкой, как раньше. Для самостоятельной индексации русского нужны отдельный
  URL, серверный русский HTML и полноценная схема canonical/hreflang — здесь
  такие страницы не создаются.
- Генератор sitemap и админские проверки приведены к той же модели.
  Карта изображений берёт существующие изображения из опубликованного HTML,
  включая главное OG-изображение, удаляет параметры кеширования и дубли.
- lastmod не меняется только от запуска генератора; при редактировании контента
  админка обновляет обе карты. После ручного изменения HTML обновите lastmod сами.
- При смене языка JS сохраняет остальные параметры URL и якорь; первый визит
  показывает тот же украинский язык, что и исходный HTML.
- Закрыт HTTP-доступ к `.env`, служебным файлам, дампам и резервным копиям;
  админка получает X-Robots-Tag: noindex. На входе обновляется ID сессии.
- В Docker Compose убрано перекрытие значений env_file пустыми переменными.

## Ожидаемые HTTP-ответы

| Адрес | Ответ |
|---|---|
| `https://tonirovka.kh.ua/` | 200, canonical на себя |
| `/robots.txt`, `/sitemap.xml`, `/image-sitemap.xml` | 200 |
| HTTP или www | 301 на HTTPS без www |
| `/index.html`, `/?lang=ru`, `/ru/` | 301 на главную без цикла |
| `/prices.html` | 301 на `/#pricing` |
| `/missing-page`, `/ru/missing-page`, `/404.html` | 404 |
| `/admin/.env`, `/data/backups/...` | 403 |
| `/admin/` | страница входа; noindex |

Смешанные query string, например `?lang=ru&utm_source=...`, не редиректятся
безусловно с потерей маркетинговых параметров: canonical остаётся на главную,
JS удаляет только lang. В sitemap есть только чистый основной URL.

## Проверки

- `python3 tests/check_seo.py` — XML/JSON, canonical, локальные ссылки,
  изображения, якоря, JSON-LD.
- `node --check js/main.js` — синтаксис JavaScript.
- GitHub Actions `SEO and redirect checks` запускает PHP lint, генератор обеих
  карт и HTTP-тесты на настоящем Apache в контейнере. Проверяет GET/HEAD,
  X-Forwarded-Proto/X-Forwarded-SSL, www, старые адреса, 404, запрет служебных
  файлов и доступность ресурсов. Это не тест реальной конфигурации Cityhost.

Старые SEO-отчёты в репозитории сохранены как история; они не доказывают
актуальное состояние сайта. Полную работу форм админки с вашей БД без доступа
к ней проверить нельзя. Имитационные оценки скорости удалены; для реальной
скорости нужен отдельный замер.

## Google Search Console после загрузки

Отправьте `https://tonirovka.kh.ua/sitemap.xml` и
`https://tonirovka.kh.ua/image-sitemap.xml`. Проверьте основной URL через
«Проверка URL» → «Проверить опубликованную страницу», затем запросите индексацию.
В отчёте об ошибках переадресации запустите проверку исправления.
Статус «Страница с переадресацией» для HTTP, www и старых URL ожидаем:
индексироваться должна конечная страница. Исчезновение всех записей об этих
URL не является целью; индексацию и сроки определяет Google.

Основания: [редиректы Google](https://developers.google.com/search/docs/crawling-indexing/301-redirects),
[языковые версии](https://developers.google.com/search/docs/specialty/international/localized-versions),
[флаги Apache](https://httpd.apache.org/docs/2.4/rewrite/flags.html).

пустой шаблон. Gitignore и Dockerignore предотвращают повторную публикацию
секретов и резервных копий.

## Дополнительная проверка HTML и сообщения 403

При прямой проверке опубликованный `image-sitemap.xml` вернул HTTP 200 на GET,
HEAD и запрос с User-Agent Googlebot. Последний тест не выполняется с IP Google
и не исключает ограничение доступа для настоящего поискового робота. Для
диагностики 403 в Search Console нужны точный URL, дата последнего чтения карты
и соответствующая запись access/error log Cityhost. XML и robots.txt сами по
себе не могут подтвердить отсутствие блокировки на nginx/WAF.

Nu HTML Checker подтвердил шесть ошибок старой страницы: два лишних закрытия
div в hero, незакрытый контейнер галереи (две связанные ошибки), img без src
в просмотрщике и style внутри noscript в body. После исправлений проверка
исходного HTML через Nu HTML Checker вернула `messages: []` (0 ошибок и предупреждений).
Генератор галереи в админке сохраняет оба закрывающих div, чтобы ошибка не
возвращалась при сохранении галереи. Просмотрщик копирует alt выбранного фото
при открытии и переключении.

Для этого дополнительного обновления на хостинге заменить:
`index.html`, `js/main.js`, `admin/gallery.php`. Правила доступа к XML не
менялись: воспроизводимого запрета для карты сайта не обнаружено.
