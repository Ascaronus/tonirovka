# Проверка админки — 21 сентября 2026

## Исправления

- Смена пароля действительно сохраняет хеш в существующем `admin/.env`. Пароль и хеш не выводятся пользователю.
- Проверка CSRF, блокировка параллельного сохранения и отказ устаревшей форме (HTTP 409) защищают редактирование сайта.
- Ошибки подключения к БД и неверные индексы обрабатываются без продолжения разрушительных операций.
- Сохранение настроек и контента использует транзакции. Восстановление таблиц выполняется одной транзакцией, с проверкой таблиц, колонок и имени файла; ошибка вызывает откат.
- Резервная копия файлов хранит исходный текст. Восстановление БД не публикует сайт автоматически: после него сохраните контент и обновите сайт из разделов цен, плёнок и галереи. Копия БД не заменяет полный бэкап хостинга.
- Загрузка изображений проверяет тип, расширение, размер и разрешение. Замена не удаляет оригинал до получения нового файла.
- Исправлены буквальные `$1` в текстах, Unicode-валидация, русские часы работы в субботу, экранирование настроек и переводов, генерация характеристик плёнок.
- Редактор настроек показывает опубликованные SEO-тексты, включая изменения из SEO-раздела. Переключение языка не заменяет их заголовком первого экрана.
- Обновление FAQ синхронизирует JSON-LD; сохранение обновляет карты сайта и данные бизнеса.
- Диагностика GD и веб-запуск SEO-монитора требуют авторизации; запуск мониторинга из браузера — POST с CSRF.

## SEO-автоматика

Разделы «SEO-автоматика» и мониторинга используют общий дизайн и меню админки.
Проверяются заголовки, description, canonical, H1, robots, изображения/alt, XML карт сайта и JSON-LD. История хранит последние 50 проверок.

Удалены случайные оценки PageSpeed, сообщения о несуществующей оптимизации изображений и удаление файлов по предположению, что они лишние. Скорость, внешняя доступность для Google и фактическая индексация не измеряются локальной проверкой. Для них нужны PageSpeed и Search Console.

Ручные SEO-поля доступны на двух языках. Автоматическая подстановка из первого экрана при сохранении контента включается отдельной настройкой и по умолчанию выключена. Мониторинг сам не переписывает контент. На странице мониторинга есть команда cron с абсолютным путём; расписание на хостинге этим обновлением не устанавливается.

## Проверка

GitHub Actions запускает PHP 8.2/Apache и отдельную MariaDB с тестовыми данными. Проверяются PHP-синтаксис, HTTP-статусы/редиректы/защищённые файлы, карты сайта, разметка, восстановление с откатом, статистика контактов, мобильные и настольные кнопки.

Playwright открывает 14 страниц админки, выполняет вход, добавление/изменение/удаление цены, сохранение контента и языков, публикацию плёнок/галереи, редактирование SEO/блоков, проверку устаревшей формы и CSRF, смену пароля с повторным входом.

Рабочая БД Cityhost в этой проверке не использовалась: имя хоста не удалось разрешить из рабочей среды. Состояние её таблиц, права пользователя и конфигурация хостинга не подтверждены. Пароли хостинга в репозиторий не добавлялись.

## Установка на хостинг

1. Сохраните полный бэкап файлов и БД хостинга.
2. Перенесите обновлённые `admin/` и `js/main.js` из основной ветки. Сохраните существующий `admin/.env`, данные, загруженные изображения и резервные копии. Каталог `tests/` и файлы CI на хостинг не нужны.
3. В опубликованном `index.html` обновите параметр версии у подключения `js/main.js` на `20260921-admin-audit`. Не заменяйте текущий контент старой копией из GitHub, если после его выгрузки редактировали сайт через админку.
4. Нужны PHP 8.2 с PDO MySQL и DOM, а также права PHP на запись в `index.html`, карты сайта, `langs/`, `images/`, `data/` и существующий `admin/.env` для смены пароля.
5. Войдите, откройте SEO-автоматику, обновите карты/разметку и выполните проверку. Проверьте сохранение одного редактируемого текста и доступность обеих XML-карт по публичному URL.

Новых обязательных таблиц для SEO-истории не требуется: она хранится в закрытом каталоге `data/`. Тестовые учётные записи создаются только тестовым скриптом внутри CI; не запускайте его на рабочем хостинге.
